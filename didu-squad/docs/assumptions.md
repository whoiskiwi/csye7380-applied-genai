# 假设文档

所有假设的取值和理由。代码里的数值以 `configs/*.yaml` 为准，本文档和配置保持一致。实验开始前冻结；冻结后修改需要记录版本。

状态：**已按 M2 校准结果和第一轮实验的分析更新（2026-10-28）**。校准过程见文末"校准记录"。

## 1. 地图和交通（`configs/assumptions.yaml` → `map`）

| 参数 | 取值 | 理由 |
|---|---|---|
| 地图 | 30 × 30 km 示意网格，3 × 3 个拥堵分区 | 不需要真实地理，便于复现和可视化 |
| 距离 | 曼哈顿距离 | 城市路网近似 |
| 车速 | 60 km/h（1 km/分钟） | 救护车鸣笛行驶的城市平均速度 |
| 拥堵系数 | 平时 1.0；晚高峰 1.2–1.5（市中心最高） | 让"最近"和"最快"不同 |
| 河流和桥 | x = 22 km 处有河，只能经 (22, 15) 的桥通过 | 对应"H1 要过桥" |
| 医院到市中心 | H1 约 16 分钟（过桥），H2 约 10 分钟，H3 约 5 分钟 | 见医院档案 |

## 2. 接线员（人工，代码模拟）

| 参数 | 取值 | 理由 |
|---|---|---|
| 报告的伤员数 | 真实值 × (1 + 误差)，误差在 ±30% 内均匀抽取，至少 1 人；多报或少报的人记为绿色 | 电话里报告的人数常常不准 |
| 报告的伤情 | 每个伤员有 20% 的概率被报重一级或报轻一级 | 报警人不是医疗人员 |
| 接警记录文字 | 由本地 LLM（qwen2.5:3b）按报告值写成 1–3 句英文接警记录，只写一次并缓存在 `data/generated/call_texts/`；文字里必须有地址、报告人数（有被困者时还要提到被困），检查不通过就重写，3 次都不通过用模板 | 作业要求用 LLM 生成合成数据；数字由代码生成保证可复现，文字只用于展示，不参与 agent 决策 |
| 调度代码 | 协议规则：心脏骤停 → E；报告有红伤或 ≥ 5 人 → D；卒中、胸痛、呼吸困难 → C；有黄伤 → B；只有绿伤 → A；其余 → Ω | 现实中由人按协议问询得出，不由 AI 判断 |

## 3. 调度代码和出警方式

| 调度代码 | 含义 | 派什么车 | 是否鸣笛 |
|---|---|---|---|
| E | 危及生命，需要立即复苏（如心脏骤停） | 最近的车，优先高级生命支持 | 是 |
| D | 最高优先级 | 高级生命支持 | 是 |
| C | 高优先级 | 高级生命支持 | 是 |
| B | 中等优先级 | 基础生命支持 | 视情况 |
| A | 低优先级 | 基础生命支持 | 否 |
| Ω | 可能不需要救护车 | 不派车（转介） | — |

## 4. 单位（`configs/resources.yaml`、`assumptions.yaml` → `units`）

| 参数 | 取值 | 理由 |
|---|---|---|
| 救护车数量 | 默认 6 辆（4 辆高级、2 辆基础）；可配置 3–8 辆 | 作业建议"如 5 辆"，并允许调整；5 辆时一起大事故就会让背景呼叫等 1 小时以上（见校准记录） |
| 车载量 | 按"载量单位"计，每车 2 个单位：红伤 2（独占一车）、黄伤 1、绿伤 2/3（最多 3 名坐姿轻伤） | 大规模伤亡事件中轻伤员常合并转运 |
| 现场停留 | 10 分钟（每次装车） | 装载和初步处理 |
| 到院交接 | 15 分钟 | 交接后车辆恢复可用，位置在医院 |
| 救援小队 | 3 支（救援、消防+救援、救援） | 覆盖解救需求 |
| 解救时长 | 被困 10–30 分钟/人，火灾 10–20 分钟/人 | 被困伤员要先解救才能转运 |
| 外地支援 | 约 20 分钟后到达【后期】 | |

## 5. 医院和人员（`configs/hospitals.yaml`）

| 参数 | 取值 | 理由 |
|---|---|---|
| 急诊床位 | H1 12、H2 8、H3 12；场景开始时已占用 H1 5、H2 3、H3 4 | 床位紧张但不至于全部堵死 |
| 医生 | H1：创伤 2、烧伤 1、急诊 2；H2：儿科 2、急诊 1；H3：急诊 3、心内 1 | 对应各院专长 |
| 护士 | H1 10、H2 8、H3 8（场景 3 中 H3 只有 6） | |
| 工作量 | 每名医生、护士容量 1.0。医生：红伤 1.0、黄伤 0.25；护士：红伤 0.5、黄伤 0.25、绿伤 1/6 | 危重病人护理强度高 |
| 红伤需要的医生 | 对口专科或急诊医生（急诊医生可以稳定伤情）；是否"能力匹配"由能力矩阵决定 | 社区医院也能先稳定再转院，但不算匹配 |
| 有效收治能力 | min(空床, 医生余量, 护士余量)，按每个伤员检查 | 床和人都要有 |
| 急诊占用时长 | 红 60、黄 45、绿 20 分钟 | 大规模伤亡事件中医院启动应急预案，急诊病人很快转入手术室或病房 |
| 区域后备人员池 | 1 名急诊医生、4 名护士，三家医院共用 | 作业要求"几家医院争夺有限的医护人员" |
| 后备人员到岗 | 分配后 30 分钟；到场景结束不归还 | 召集和路程 |
| 接收上限 | 医院按红、黄、绿报数，不对单个病人讨价还价；报数可以低于实际能力（为危重病人留余量），但不能高于 | 和现实做法一致 |
| 拒收 | 只能在病人出发前；出发时床位和人员已预留，出发后不能拒收 | 美国急诊不能拒收已送到门口的病人 |

## 6. 伤情和结果（`assumptions.yaml` → `outcomes`）

| 参数 | 取值 | 理由 |
|---|---|---|
| 分诊 | START：红、黄、绿、黑 | 标准大规模伤亡分诊方法 |
| 红伤窗口 | 从呼叫起 60 分钟内到达能力匹配（2）的医院 | "黄金一小时"的通行说法 |
| 黄伤窗口 | 240 分钟内到达能力匹配的医院 | 延迟处理类 |
| 黄伤恶化 | 呼叫后 90 分钟仍未离开现场 → 变为红伤，红伤窗口从恶化时刻重新计算 | 体现时间紧迫度 |
| 绿伤 | 到达任何能接收（≥ 1）的医院即算救到 | 轻伤 |
| 黑伤 | 不转运，不计入救到或未处理 | 期待治疗类 |
| 未处理的危重事故 | 含红伤、且红伤没有全部在窗口内送到能力匹配医院的事故 | |

## 7. 场景（`configs/scenarios/*.yaml`）

| 场景 | 主要事故 | 背景呼叫 | 交通 | 医院处境 |
|---|---|---|---|---|
| S1 高速连环车祸 | t=5，8 人（2 红 3 黄 3 绿），2 人被困 | 11 起，必含心脏骤停和卒中 | 晚高峰 | 正常 |
| S3 聚餐食物中毒 | t=10，20 人（3 红 7 黄 10 绿） | 12 起，必含 2 起胸痛 | 平时 | H3 少 2 名护士 |
| S5 两起大事故同时发生 | t=5 车祸 8 人 + t=12 食物中毒 20 人 | 10 起，必含心脏骤停 | 晚高峰 | 正常 |

背景呼叫类型比例：心脏骤停 10%、卒中 10%、胸痛 20%、摔倒 25%、呼吸困难 20%、其他 15%；10% 为儿童；位置按 4 个热点的高斯混合抽样。呼叫在 120 分钟内到达，模拟最长 420 分钟。

## 8. 协商和模型

| 参数 | 取值 | 理由 |
|---|---|---|
| 协商最多轮数 | 3，之后由总指挥裁决 | |
| 失败重试 | 1 次，之后退回规则 | 保证每次运行都能完成 |
| 医院报告刷新 | 接收能力有实质变化（某级从 0 变为非 0 或反之，或变化 ≥ 3）或超过 20 分钟 | 医院状态看板的更新方式；也减少模型调用 |
| 决策耗时 | 0 模拟分钟 | LLM 快慢不影响结果 |
| MVP 后端 | mock（测试）+ Ollama 开源模型，在学校 Explorer 集群的 GPU 上运行；temperature 0；全部响应缓存 | 不花钱、可复现 |
| strong 档 | qwen2.5:14b：医院协调、总指挥 | 判断最难、出错代价最大；模型大小约为 fast 档的 5 倍 |
| fast 档 | qwen2.5:3b：事故评估、调度员、三家医院 | 输入结构化或目标单一、调用频繁 |
| 总指挥改派 | 只能改派车上没有病人、并且是多派的车：一起事故保留和它还需要的趟数一样多的空车（离现场最近的几辆），多出来的才能改派；目标事故必须更紧急 | 现实中总指挥可以跨事故调车；只有完整 MA 有这个能力。正在现场等被困者解救的车不能调走，因为被困的往往伤得最重 |
| 角色规则检查 | agent 违反自己提示词里的规则（例如同样适合时改派到更远的医院）时，告诉它违反了哪条，重答 1 次；第二次的回答无论如何都采用，只记录次数 | 决定权留在 agent；给小模型一次纠错机会；违规次数作为结果的一部分报告 |

## 校准记录（M2）

第一次用基线跑三个场景时，系统严重过载（S1 平均响应 87 分钟，红伤窗口内送达约 3%），所有方法都接近失败，无法比较。逐项排查后做了以下调整：

| 调整 | 原值 | 新值 | 原因 |
|---|---|---|---|
| 车速 | 50 km/h | 60 km/h | 到场时间 20–25 分钟，不符合城市急救 |
| 晚高峰拥堵 | 最高 2.0 | 最高 1.5 | 同上 |
| 车载量 | 每车最多 2 人 | 载量单位（绿伤最多 3 人） | 轻伤员合并转运是通行做法 |
| 急诊占用 | 红 120 / 黄 60 / 绿 30 | 60 / 45 / 20 | 床位长期占满导致救护车在现场等床，全系统堵死 |
| 床位 | 10 / 8 / 10 | 12 / 8 / 12 | 同上 |
| 呼叫时段 | 90 分钟 | 120 分钟 | 90 分钟内 11 起背景呼叫，本身就需要 5–6 辆车全职处理 |
| 救护车 | 5 辆 | 6 辆 | 5 辆时 S1 平均响应仍约 1 小时 |
| 食物中毒人数 | 30 | 20 | 5–6 辆车没有外地支援时无法处理 30 人；外地支援属于后期功能 |

调整后，S1 和 S3 处于"紧张但可以改进"的状态；S5（两起大事故同时发生）仍然严重过载，作为压力测试保留。
