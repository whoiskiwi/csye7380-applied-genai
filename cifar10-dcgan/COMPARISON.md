# Manual baseline vs. AI-generated DCGAN — Comparison

Both notebooks solve the **same task** — a DCGAN that generates CIFAR-10 **`automobile`** images
(32×32×3, latent dim 100, `tanh` output in [-1, 1]) and demonstrates **controlling the noise vector**.
They differ in *how the training is engineered*.

- **Manual baseline** (`manual/dcgan_manual.ipynb`): a faithful port of the in-class `gan.ipynb` recipe —
  same `GAN` class structure and the same `train_on_batch` loop — with Dense layers replaced by
  convolutions. Deliberately "the class way," so it is simple but not efficient.
- **AI-generated** (`ai_generated/dcgan_ai.ipynb`): generated by Claude Code from `ai_generated/PROMPT.md`,
  then hand-tuned. Rewrites the training engine with modern best practices.

## 1. Key differences

| Aspect | Manual baseline | AI-generated (optimized) |
|---|---|---|
| Origin | Hand-ported from class `gan.ipynb` | Generated from a prompt (`PROMPT.md`) + tuned |
| Data feeding | `np.random.randint` index slicing every step | **`tf.data`** pipeline: `cache` → `shuffle` → `batch` → `prefetch` |
| Training step | `generator.predict()` + 2× `discriminator.train_on_batch` + 1× `combined.train_on_batch` | **one `@tf.function` step** with `GradientTape` updating D and G in a single compiled graph |
| Graph/retracing | train functions **retrace**; Python↔graph crossing every step | compiled **once**, no per-step retracing |
| Discriminator output | `sigmoid` + `binary_crossentropy` | **logits** + `from_logits=True` (more numerically stable) |
| Label handling | hard 0/1 labels | **one-sided label smoothing** (real → 0.9) |
| Weight init | Keras default (Glorot) | **`RandomNormal(0, 0.02)`** (DCGAN paper) |
| Keras 3 safety | **breaks by default** — needs separate optimizers + per-step `trainable` toggle, else D is frozen and output is pure noise | **immune** — `GradientTape` applies generator gradients only to generator variables |
| Generator model | `Sequential` wrapped in functional `Model` | clean `Sequential`, `use_bias=False` before BatchNorm |
| Noise-control demos | linear interpolation + per-dimension sweep | linear interpolation + per-dimension sweep + **noise-magnitude scaling** |
| Instrumentation | prints loss/acc per interval | records **ms/step** + loss curves + printed summary |

## 2. Why the AI version is faster (the main point)

The baseline does **four** separate framework calls per step and runs the generator twice
(`predict` for fake images, then again inside `combined`), each crossing the Python↔graph boundary and
triggering retracing. The optimized version fuses the entire step — sample noise → generate → score
real & fake → compute both losses → apply both gradient updates — into a **single `@tf.function`**, so
after the first call it runs as one cached graph with no Python overhead. Combined with a `tf.data`
input pipeline (prefetching batches on the CPU while the GPU computes), this is where the speed-up comes
from.

## 3. Results (fill in from the Colab GPU run)

> Train both notebooks on Colab (Runtime → GPU → Run all) and paste the numbers here.

| Metric | Manual baseline | AI-generated |
|---|---|---|
| Hardware / GPU | Colab GPU (TF 2.20) | Colab GPU (TF 2.20) |
| ms / step | 118 ms/step | **84.5 ms/step** (~1.4× faster) |
| Steps (or epochs) | 4000 steps | 60 epochs (2760 steps) |
| Total wall-clock | 7.8 min | **4.2 min** |
| Final D loss / G loss | 0.61 / 1.19 (D acc 65%) | 1.06 / 1.66 (balanced, stable) |
| Visual quality (subjective) | recognizable cars, blurry | **sharper cars** — bodies, windshields, wheels, reflections |

**Speed:** the AI version is **~1.4× faster per step** (84.5 vs 118 ms) *and* uses fewer steps, despite a
larger batch (128 vs 64). The gap comes from the fused `@tf.function` step + `tf.data` prefetch vs. the
baseline's `predict` + multiple `train_on_batch` + per-step `trainable` re-tracing.

**Stability:** the AI losses sit in a healthy balanced band (D≈1.0, G≈1.6) with no sign of collapse; the
noise-magnitude sweep is especially clean — `0×` gives the blank "mean" image and larger magnitudes give
progressively sharper, more diverse cars.

## 4. Takeaways

- Same architecture family and same data → **the difference is engineering, not model capacity.**
- `@tf.function` + `tf.data` is the single biggest lever for training-loop speed in TF/Keras.
- DCGAN stabilizers (0.02 init, label smoothing, logits loss, dropout) tend to give the optimized
  version cleaner samples at equal step counts.
- The noise-vector studies (interpolation, dimension sweep, magnitude scaling) show both models learn a
  **smooth, controllable latent manifold** rather than memorizing images.
