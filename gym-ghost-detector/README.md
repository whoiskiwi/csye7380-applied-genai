# Gym Member Churn — Classification (Colab-ready)

Predicts whether a gym member will **churn** (cancel their membership — i.e. leave the
service) using a **synthetic dataset generated by Claude** (6,000 members, ~27% churn).

The dataset is created with *designed* churn drivers (contract type, tenure, weekly visits,
distance to the gym, …), so after training we can verify that the models rediscover the
ground-truth patterns — a clean sanity check for the whole pipeline.

## Folder contents


## How to run in Google Colab

1. Go to [colab.research.google.com](https://colab.research.google.com) → **File ▸ Upload notebook**
   → pick `gym_churn_classification.ipynb`.
2. **Runtime ▸ Run all.** The notebook **generates the synthetic data itself** (no upload
   needed), trains the models, and shows all plots and metrics.

## What the notebook does

1. Setup & imports
2. **Generate synthetic data** (6,000 rows) with realistic, designed churn patterns
3. EDA — churn balance, correlations, churn rate by contract, feature distributions by churn
4. Train/test split (80/20, stratified, `random_state=42`)
5. Three models in preprocessing Pipelines: **Logistic Regression, Random Forest, SVM (RBF)**
6. Hyperparameter tuning with **`GridSearchCV`** (5-fold CV, scoring = ROC-AUC)
7. Evaluation — accuracy, precision, recall, F1, confusion matrix, **ROC curves**
8. Feature importance (Random Forest importances + Logistic Regression coefficients)
9. Interpretation & business recommendations

**Preprocessing note:** the data mixes numeric and categorical features, so each model runs
inside a `ColumnTransformer` that **StandardScales** the numeric columns and **one-hot encodes**
the categorical ones (`contract_type`, `personal_trainer`, `signup_promo`, `gender`).

## Designed churn drivers (ground truth)

Built into `generate_data.py` so results can be checked:

| Driver | Effect on churn |
|---|---|
| `contract_type` = Month-to-month | strongly **↑** (Annual strongly **↓**) |
| `avg_weekly_visits` | **↓** (engaged members stay) — the top driver |
| `tenure` (months) | **↓** (loyal members stay) |
| `distance_km` (home → gym) | **↑** |
| `monthly_fee` / `total_paid` | fee **↑**, total paid **↓** (invested members stay) |
| `personal_trainer` = No | **↑** |
| `signup_promo` = Yes | **↑** (promo members lapse after the promo) |
| `num_group_classes`, `extra_spending` | **↓** (more engagement → stickier) |

A Gaussian noise term keeps the task realistically hard (models land at AUC ≈ 0.81, not a
trivial 1.0).

## Results (held-out test set)

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
|-------|:---:|:---:|:---:|:---:|:---:|
| Logistic Regression | 0.771 | 0.621 | 0.422 | 0.503 | **0.813** |
| Random Forest | 0.765 | 0.633 | 0.340 | 0.443 | 0.809 |
| SVM (RBF) | 0.762 | 0.629 | 0.319 | 0.423 | 0.811 |

**Top churn drivers found by the models:** `contract_type` (Month-to-month),
`avg_weekly_visits`, `tenure`, `total_paid` — exactly the drivers designed into the data.
Logistic Regression edges out on AUC and is fully interpretable.

> The modest **recall** (~0.4) is expected: with a ~27% churn base rate and a 0.5 decision
> threshold, the models stay conservative. Lowering the threshold trades precision for recall
> depending on how aggressive the retention campaign should be.

`scikit-learn pandas numpy matplotlib seaborn`.
